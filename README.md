# 本地双语翻译

一个简单、快速、隐私优先的 Chrome 双语网页翻译插件。英文原文保持不变，中文译文以清晰的阅读层次插入原文下方，效果类似精简版“沉浸式翻译”。翻译请求只发送到 Mac 本机的 Ollama。

## 特点

- 中英对照，不破坏网页原有 DOM 文本和链接
- 优先翻译屏幕中可见内容，分批、并发请求提升首屏速度
- 自动模式只翻译当前视口附近内容，滚动时按需继续，减少无效等待
- 相同文本在送入模型前自动去重，并缓存模型及连接状态
- 使用约 523 MB 的 `qwen3:0.6b` 本地模型
- 结构化输出保证每个英文段落与中文译文一一对应
- 支持深色网页、标题层级、列表和正文的自适应双语排版
- 逐段检测实际背景色并计算文字对比度，兼容同页黑底与白底区域
- 一键翻译、一键移除，可选自动翻译
- 可指定域名自动翻译，并持续处理站内跳转和动态加载内容
- 批量输出异常时自动拆分重试，避免整页一起失败
- 翻译前检查 Ollama 与所选模型，服务离线时立即给出明确提示
- 插件更新后可自动向已打开的网页注入脚本，无需手动刷新标签页
- 无云端 API Key，内容不离开本机

## 1. 安装 Ollama 和模型

从 [Ollama 官网](https://ollama.com/download) 安装 macOS 版本并打开，然后在终端运行：

```bash
ollama pull qwen3:0.6b
```

`qwen3:0.6b` 体积约 523 MB，速度优先。若机器内存允许且更看重翻译质量，可使用：

```bash
ollama pull qwen3:1.7b
```

随后在插件设置中把模型改为 `qwen3:1.7b`。

### 解决 Chrome 扩展的 HTTP 403

Ollama 默认可能拒绝来自 `chrome-extension://` 的 POST 请求。打开插件的“设置与连接测试”，复制页面生成的专属命令。命令格式如下，其中插件 ID 会自动填写：

```bash
launchctl setenv OLLAMA_ORIGINS "chrome-extension://当前插件ID"
```

随后从菜单栏彻底退出 Ollama，再重新打开。这样只授权当前插件，不会向所有 Chrome 扩展开放接口。新版“测试连接”会同时验证 GET 和 POST，不会再出现“显示模型已安装但翻译仍然 403”的误判。

## 2. 加载 Chrome 插件

1. Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目文件夹：`本地模型翻译`。
5. 将“本地双语翻译”固定到工具栏。

## 3. 使用

打开英文网页，点击工具栏中的插件，再点击“翻译当前网页”。译文会逐批显示在英文下方。点击“移除中文译文”可恢复页面。

插件设置页可测试 Ollama 连接，调整每批段落数和并发数。默认 `8 × 2` 对 Apple Silicon 是较稳妥的速度配置；如果模型输出偶尔错位，可将每批段落数降至 4。

## 限制

- Chrome 内部页面、Chrome 网上应用店和 PDF 内置阅读器不允许普通内容脚本注入。
- 画布、图片、视频字幕以及封闭 Shadow DOM 中的文字不会被翻译。
- 网页后续动态加载的新内容需要再次点击翻译。
- 超小模型追求速度，专业术语质量不及大模型；可在设置中换成本地更大模型。

## 文件说明

- `content.js`：识别英文段落、调度批次、插入译文
- `background.js`：访问本机 Ollama 并约束结构化翻译结果
- `content.css`：中英对照阅读排版
- `popup.*`：工具栏控制面板
- `options.*`：模型与性能设置
