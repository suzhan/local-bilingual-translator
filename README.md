# 本地双语翻译 v0.4.0

一个简单、快速、隐私优先的 Chrome 双语网页翻译插件。英文原文保持不变，中文译文以清晰的阅读层次插入原文下方，效果类似精简版“沉浸式翻译”。翻译请求只发送到 Mac 本机的 Ollama。

## 特点

- 中英对照，不破坏网页原有 DOM 文本和链接
- 优先翻译屏幕中可见内容，首批最多 2 段，完整译文逐段显示，不等整批结束
- 自动模式只翻译当前视口附近内容，滚动时按需继续，减少无效等待
- 相同文本自动去重；译文缓存可跨后台休眠复用，按地址、模型和温度隔离，浏览器重启后清除
- 使用约 523 MB 的 `qwen3:0.6b` 本地模型
- 结构化输出约束段落数量；流式显示后仍校验最终结果，格式异常时撤销该批临时译文并拆分重试（模型语义质量仍需人工判断）
- 支持深色网页、标题层级、列表和正文的自适应双语排版
- 逐段检测实际背景色并计算文字对比度，兼容同页黑底与白底区域
- 一键翻译、一键移除；移除会中止在途请求、取消排队并暂停自动翻译，点击翻译可恢复
- 可指定域名自动翻译，并持续处理站内跳转和动态加载内容
- 弹窗可将当前网站加入或移出自动翻译名单
- 支持“不使用插件”和“不自动翻译”两个域名排除名单
- 批量输出异常时自动拆分重试，避免整页一起失败
- 直接发送翻译请求，省去翻译前的额外连接检查；错误明确显示，设置页保留独立连接测试
- 插件更新后可自动向已打开的网页注入脚本，无需手动刷新标签页
- 无云端 API Key，内容不离开本机

## 1. 安装 Ollama 和模型

从 [Ollama 官网](https://ollama.com/download) 安装 macOS 版本并打开，然后在终端运行：

```bash
ollama pull qwen3:0.6b
```

`qwen3:0.6b` 体积约 523 MB，速度优先。若机器内存允许且更看重翻译质量，可使用：

```bash
ollama pull qwen3:1.7b
```

随后在插件设置中把模型改为 `qwen3:1.7b`。

### 解决 Chrome 扩展的 HTTP 403

Ollama 默认可能拒绝来自 `chrome-extension://` 的 POST 请求。打开插件的“设置与连接测试”，复制页面生成的专属命令。命令格式如下，其中插件 ID 会自动填写：

```bash
launchctl setenv OLLAMA_ORIGINS "chrome-extension://当前插件ID"
```

随后从菜单栏彻底退出 Ollama，再重新打开。这样只授权当前插件，不会向所有 Chrome 扩展开放接口。新版“测试连接”会同时验证 GET 和 POST，不会再出现“显示模型已安装但翻译仍然 403”的误判。

## 2. 加载 Chrome 插件

1. Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目文件夹：`本地模型翻译`。
5. 将“本地双语翻译”固定到工具栏。

## 3. 使用

打开英文网页，点击工具栏中的插件，再点击“翻译当前网页”。每段译文生成后会显示在英文下方，不用等整批生成结束。点击“移除中文译文”可恢复页面。

插件设置页可测试 Ollama 连接。默认每批最多 8 段、全局并发 1；首批最多 2 段，后续按 1800 字符总预算自动缩小批次。并发上限由所有标签页共享；提高并发不保证更快。原默认 16 段在更新时迁移为 8 段。模型调用后保留 30 分钟以减少重新加载，这段时间会占用模型内存。

## 限制

- Chrome 内部页面、Chrome 网上应用店和 PDF 内置阅读器不允许普通内容脚本注入。
- 画布、图片、视频字幕以及封闭 Shadow DOM 中的文字不会被翻译。
- 自动模式会处理视口附近新内容；手动模式若页面新增内容，可再次点击翻译。移除译文后自动模式暂停，直到再次点击翻译或重新开启自动设置。
- 超小模型追求速度，专业术语质量不及大模型；可在设置中换成本地更大模型。

## 文件说明

- `content.js`：识别英文段落、调度批次、插入译文
- `background.js`：流式访问 Ollama、全局调度、会话缓存、超时和取消
- `translation-core.js`：共享的分批、流式 JSON 项解析、缓存键逻辑
- `tests/`：Node 回归测试、浏览器交互测试页和本机实测脚本
- `优化说明.md`：改动、测试范围、升级与性能对比方法
- `content.css`：中英对照阅读排版
- `popup.*`：工具栏控制面板
- `options.*`：模型与性能设置

## 从旧版升级

退出正在运行的翻译，先备份旧目录。把本压缩包中的项目文件复制到原扩展目录，然后在 `chrome://extensions/` 点击该扩展的“重新加载”，并刷新要翻译的网页。**这次更新改变了后台通信协议，已打开网页必须刷新一次。** 使用原目录可保留原扩展 ID、设置和 Ollama 授权；不要另建一个不同路径重复加载。

## 验证与测速

需要 Node.js 20 或更新版本，不需要安装 npm 依赖：

```bash
cd /Users/suzhan/Documents/ChatGPT/本地模型翻译
node --test tests/*.test.cjs
node tests/benchmark.cjs
```

测速前启动 Ollama。若使用其他模型：

```bash
OLLAMA_MODEL=qwen3:1.7b node tests/benchmark.cjs
```

对比脚本使用内置的 16 句英文，分别比较旧版批量等待、新版逐段流式和缓存命中。它不改变 Ollama 系统配置、不卸载模型；先预热后交替测试三轮，输出首段/总耗时和译文供核查。首段计时在后台收到完整段落时结束，不包含真实页面绘制。**更早显示不等于整页生成一定更快**；真实结果取决于模型、Mac 硬件、段落长度与同时运行的其他任务。

浏览器交互测试：终端运行 `python3 -m http.server 8765`，在 Chrome 打开 `http://127.0.0.1:8765/tests/browser.html`，点击“运行全部交互测试”。这使用模拟 Chrome 消息和模型响应，验证页面逻辑，不测试真实扩展权限、MV3 生命周期或 Ollama 推理。
